## Implemented behavior

`config/academy-server.toml` in the game instance now exposes `ac.ability.category.<location>.skills.<skill>.enabled` and `destroy_blocks` for all 41 canonical skill objects. An existing matching file under a world's `serverconfig` overrides that instance config. This NeoForge 21.1.252 path was confirmed from the actual fresh singleplayer log, generated readme and ConfigTracker.resolveBasePath; newly generated worlds otherwise use the instance config. `defaultconfigs` supplies a template on first creation. The three generic courses share `generic` settings across their four registered category instances. Defaults remain true. All 50 category instances and their original IDs remain registered.

Dependency conditions and UI parent edges capture the dependency's enabled state when the server config loads. Disabling a parent then makes the child a root; disabling an additional dependency removes that condition independently. Level, developer tier and `AnySkillOfLevel` remain. Reloading live booleans does not rebuild those captured relationships. Both learning validators and the developer/terminal skill tree use this view. Enabled controllable skills alone contribute to the level-up denominator; zero preserves the source's full-progress case.

New preset selection excludes disabled skills. Already learned data, passive bonuses and existing mapped presets remain. Existing learned mapped disabled skills can still activate, matching the original `PresetData`/`ClientRuntime` path. Actual NBT restoration also retains these mappings. This behavior is deliberate source compatibility; an enabled setting is not a universal revocation of old bindings.

State synchronization carries both the captured server graph and live flags. A remote client cannot choose server dependencies from its local file. This explicit graph transport is a modern authority adaptation beyond the original whole-config transport. Singleplayer does not feed an older client snapshot back into the shared integrated-server configuration.

`worldsWhitelistedDestroyingBlocks` accepts modern dimension resource IDs and legacy vanilla IDs `0`, `-1`, `1`. The whitelist overrides global `destroyBlocks`; it never overrides a skill's local false. Local terrain flags apply to source AbilityContext paths, including beams, Ground Shock, Directed Blastwave, Storm Wing, Plasma Cannon terrain and Shift Teleport placement. Painting/item-frame protection is centralized after the calculation event, while ordinary living damage remains enabled.

Source exceptions are retained: mining rays ignore their local flag but obey the global/world event pipeline; Arc ignition and Magnetic Manipulation extraction directly write terrain; Vector Deviation fireball explosions use `mobGriefing`. Modern chunk, build, region and cancellable event protections remain where already integrated.

Vector Deviation and Reflection share configurable ordered entity difficulty and exclusion lists under `ac.ability.category.vecmanip.common.affected_entities`. `difficulties` entries use `name=value`. First matching class wins, exclusions include subclasses, unknown names are ignored, and unmatched difficulty is 1. The seven source default aliases are supported. Modern vanilla resource IDs resolve official public `EntityType` generic classes; modded types without a public class signature use exact registered type matching. Other historic entity-name aliases and modded inheritance mapping remain compatibility gaps. Finite nonnegative difficulty validation is a modern saved-state safety adaptation. Values capture at world config loading; the original Scala object captures once on first access. Live skill reload does not rebuild the entity rules.

This private development increment ports AcademyCraft 1.0.7 `TilePhaseGen`, `TileGeneratorBase`, `ContainerPhaseGen`, `BlockPhaseGen`, `GuiPhaseGen`, and `RenderPhaseGen` to Minecraft 1.21.1/NeoForge 21.1.252. Original GPLv3/additional notices and LambdaLib MIT notices remain. It adds no media, sale, publication, distribution, or install authorization.

## Genuine acquisition and finite generation

`academy:phase_gen` is a real native block, item, block entity and menu. Recipe `academy:classic/phase_gen_08` is the exact original two-row grid: low crystal/frame/low crystal; empty matter unit/empty cell/empty matter unit. The existing low crystals, machine frame, empty/filled matter units, genuine phase source fluid, fluid-container capabilities, world collection and phase-liquid world generation are reused without replacement or duplication. The registered source recipe yields one empty generator. Hardness is 2.5, harvest level is pickaxe 1/stone tier, collision is a full cell, and the block has no facing or active state.

The tank holds8000 mB; each filled matter unit supplies1000 mB. Each server tick first generates, then publishes source snapshots when due, then acquires at most one unit, then charges its native IF item. Generation drains `min(100, integer((6000-energy)/0.5))`mB, limited by the finite actual tank, and credits0.5 IF per actual mB. Thus one complete phase unit yields500 IF and source generation is at most50 IF/tick. A fractional buffer headroom below0.5 IF does not burn fuel. A full6000 IF buffer stops generation.

Acquisition preserves the source's strict `free tank >1000 mB` boundary; exactly1000 free blocks it. The input must be the genuine filled phase matter variant, and the return slot must be empty or contain fewer than16 genuine empty matter units. Acquisition adds one whole1000 mB, debits one whole filled unit and refunds exactly one empty shell. A full, foreign, or filled-phase return slot blocks the transaction. Newly acquired fluid starts generating on the next tick because source generation has already happened.

The actual original `IFConstants.LATENCY_MK1` is 50 IF/tick. Both the generator's native item offer and wireless capability report50. The native source IF manager also honors each item's own bandwidth: an empty Energy Unit accepts20 IF/tick, while an empty portable developer can accept50. Only actual accepted IF leaves the finite buffer. Unsupported/full items cannot debit it. Wireless `getProvidedEnergy` debits actual available IF without its own bandwidth limit, matching the source API; the existing real graph applies the50 IF limit and checks the actual storage delta.

The three raw/menu slots are source 0 liquid input `(45,12)`,1 matter return `(112,51)`, and2 IF item output `(42,80)`. The actual native hotbar/inventory uses the original TechUI coordinates. Shift-click prefers IF slot2, then filled phase slot0. All36 real player slots work.

Old menu IDs/nonces, wrong origin, distance, removed tile and bad local node passwords are rejected. Existing Solar, Former, Fusor and developer paths remain in their established routes. No adjacent power source, fake graph membership, creative IF or invented fuel is supplied by the implementation.

## Persistence, lifecycle and explicit modern adaptations

The tank and all native item components persist. The native block entity also saves the finite fractional IF buffer. This deliberately fixes a source omission: original `TileGeneratorBase` never wrote its private energy to NBT, so original earned IF vanished on restart. Conserved buffer persistence follows the already implemented modern Solar adapter; it is an explicit lifecycle adaptation, not a claim about original1.7.10 NBT.

Source network clocks remain separate: fluid every10 server ticks and energy every20. The snapshots are captured after generation but before unit acquisition/item charging. Modern partial block entity packets keep the untouched client field. Initial chunk tags contain both fields and no inventory reset. Native menu data transfers the full finite IF double using four16 bit words and the mB amount using one word.

Native fluid capabilities accept only the existing genuine phase fluid, expose copied snapshots, support simulation and capacity-bound actual fills/drains on all faces. Modern `drain(FluidStack)` rejects a foreign requested fluid. Original `TilePhaseGen` accidentally ignored that argument's identity, despite its separate `canDrain` check; the modern contract deliberately corrects that mismatch. Negative/nonfinite IF requests and malformed persisted energy/liquid are rejected or clamped to finite capacities. Modern empty stacks avoid the original zero-count stack's free empty-shell bug. The source transfer range `[4,40)` skipped the first real player slot and extended beyond the39 slot menu; the modern range `[3,39)` corrects that indexing error.

Only a live authoritative tile at its real loaded world position exposes fluid/IF/item capabilities. Removed/replaced tiles and cached handlers cannot provide phantom payloads. Native breaking drops each genuine inventory stack and the generator's ordinary block loot once; tank fluid and buffer IF are discarded on block destruction as in the source, rather than being invented as additional items.

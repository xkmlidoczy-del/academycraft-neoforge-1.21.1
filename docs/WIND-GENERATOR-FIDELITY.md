## Literal source behavior

- Recipes10–13 are respectively iron ingot/frame/convert-component, iron bars/redstone/iron bars, frame plus constraint plates/convert-component plus frame, and four reinforced iron plates around iron bars. Each outputs one original item. Existing authentic materials retain their current registry identities.
- Base occupies `(0,0,0)` and `(0,1,0)`. Main occupies `(0,0,0)`, `(0,0,-1)`, `(0,0,1)` before the original four horizontal rotations. Pillar occupies one full collision/selection cell. All blocks use source hardness4 and pickaxe harvest level2. Original placement yaw0/90/180/270 maps NORTH/EAST/SOUTH/WEST, independent of modern vanilla facing conventions.
- Base scans upward beginning two cells above its origin. It needs8–40 contiguous pillars followed by a main origin. Too few pillars with an ordinary missing cell is BASE_ONLY; a short tower that reaches a main, an auxiliary main, a missing top after8 pillars, or41 pillars is NO_TOP. Main scans downward from its origin-1, accepting the upper base block after8–40 pillars. Base height does not enter generation.
- Main altitude70 or lower yields7.5 IF/tick. Altitude160 or higher yields15 IF/tick. Between them the literal formula is `15*(.5+.5*clamp((mainY-70)/90,0,1))`. There is no source wind vector, gust, random drift, sky visibility test, weather/daytime factor, biome factor or dimension factor.
- A structurally complete tower generates only with a complete main and the authentic fan installed. The original168-cell plane consists of `(i,j,-1)` for both i/j=-6..6 excluding `(0,0,-1)`, rotated with the main. Every non-air source material is an obstacle. Obstruction hides the entire fan and prevents its visible spin; it deliberately does not stop IF generation. The modern air-material equivalent is BlockState.isAir.
- The fan is stack1/maxDamage100. Source has no fan wear, damage debit, replacement timer or wind-strength-dependent spin. The fan's existing damage/custom components remain intact.
- Base buffer is20,000 IF; MK3 bandwidth is300 IF/tick. Item charging offers min(stored IF,300), then the genuine item's own capacity/bandwidth constrains actual acceptance. Wireless getProvidedEnergy is finite extraction; the current graph enforces the generator bandwidth before requesting IF.
- Source update order is generation using the prior tower state,20-tick pre-item-charge energy snapshot,10-tick tower refresh, then item charging. Main checks tower/obstacles every10 ticks and publishes fan inventory every20 ticks. Breaking a pillar preserves base/main components and stops generation after the original refresh. Breaking any cell of one component tears down that component and refunds its actual root inventory once.
- Base inventory GUI slot is(42,80), main fan slot(78,9); the same source hotbar/reversed-row player mapping and all36 transfer slots are retained. Base slot manually accepts genuine IF items, while original base automation accepts any item. Main manual/automation slot accepts only the fan. Base has inventory/info/wireless pages; main has inventory/info only. Base info uses the distinct source buffer color0xff25f7ff and altitude of the base itself. Main info shows main altitude. Base four-state main/middle/base icon alpha triples are(.2,.2,1),(.2,1,1),(1,1,1),(.6,1,1).

## Explicit modern lifecycle and security adaptations

The original created separate generator/inventory tiles in both base cells and all three main cells. An unchanged-source executable witness confirms the upper base can independently generate with≥9 pillars. This port gives only the origin inventory/IF ownership. Auxiliary inventory menus resolve to that same live origin; auxiliary capability providers and persisted payloads are absent. Multiple auxiliary graph links cannot multiply300IF bandwidth. Fan/base inventories are not duplicated across siblings.

Placement validates every component cell's replaceability, loaded chunk, build height, border, edit permission and entity collision before any debit. It snapshots replaced states/NBT and rolls back failed multi-cell placement. It does not apply arbitrary item-carried block-entity NBT to a newly placed generator. Teardown uses an origin lock and exact block/PART/FACING identity, retains foreign replacement cells, drops only the actual matching root inventory once, and suppresses secondary component block loot. Normal clicked-cell native loot is the single block item. Unloaded neighboring cells defer integrity destruction and forbid generation until the component is available; no force loading is introduced. A linked root spanning an unloaded neighboring chunk remains dormant in the existing graph.

Original TileGeneratorBase omitted energy NBT. Modern root IF persists as finite clamped double, alongside genuine ItemStack components and native direction/PART states. Malformed/negative/nonfinite IF loads and requests are fenced. Retained replaced/removed capabilities and item handlers cannot expose, debit, insert or reset payloads. Stale wireless menu IDs/nonces, wrong tile/origin, wrong menu kind and out-of-range senders are rejected through current protocol guards. The client has presentation snapshots and native menu copies; it cannot alter server tower state or payloads. Fan remote rendering updates through the original20tick authoritative publication clock.

Original main renderer used an infinite AABB. Modern main requests offscreen rendering with an8-block finite box containing the complete swept original7.2081-block-radius mesh; this avoids infinite engine culling bounds without shrinking geometry. Resource reload clears missing/broken meshes instead of retaining an old resource pack's mesh.

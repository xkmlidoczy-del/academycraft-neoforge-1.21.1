## Delivered gameplay and learning

`AdvancedMineRaySession` implements the actual shared original `MRContext`, configured independently by EXPERT and LUCK. Native `MineRayExpert` and `MineRayLuck` have independent UUID hold maps, nonce histories, tokens and lifecycle through the shared native controller. Neither calls or aliases Basic. Original range20, harvest limit5, speed .5F→1F, EXP .0003F and cooldown60F→30F are shared. Expert pays25F→15F CP each tick and300F→200F startup overload, Fortune0. Luck pays50F→35F CP and350F→300F overload, Fortune3. Source Float mastery and interpolated coefficients are captured once, cooldown truncates to Int, and original overload-floor/first-acquisition/no-subtraction/failed-CP-final-work/captured-hardness/replacement-block quirks remain.

Acquisition posts the canonical skill-block event and applies modern protection; rejected acquisition rechecks next tick. Continuing mining does not invent classic harvest/hardness recapture. Break callback uses the current state/block entity, centered .5-volume/1-pitch break sound, one native item-drop path, then setAir. No entity damage, explicit vanilla XP, equipped-tool mutation, Silk Touch inheritance, durability loss or duplicated loot is introduced. The final modern native guard is kept. Like the original void callback, pure MRContext still awards skill EXP after a callback even if that new guard prevents actual removal; the compiled native fixture makes this edge explicit.

The common `SkillAvailability` union is reused without an alternate learning allowlist. Canonical metadata remains50skills. Expert requires level4 and learned Basic mastery.8; Luck requires level5 and learned Expert mastery1. Both require ADVANCED. Pure finite development actually completes11/15 stimulations after176/240 ticks and spends7040/9600 IF, versus the original UI estimate6600/9000. Completion revalidates prerequisites, no target is granted by the learning fixture, learning leaves mastery0, and binding remains a separate genuine preset action.

## Explicit modern differences

- Modern negative build height makes classic sentinel(-1,-1,-1) a valid block. A separate capture boolean ensures this real coordinate receives first-acquisition/permission/harvest/hardness, without filtering the original packet sentinel. Classic's reachable positive-height behavior is unchanged. Basic is addressed by a separately reviewed package, not this one
- Modern block states/tool tags replace integer metadata/arbitrary harvest tiers. The pure World contract carries the previous-target metadata position exactly, but native harvest adapter uses the target state and existing vanilla/tool-tag approximation. Arbitrary modded level4/5 or metadata-dependent tiers cannot be reconstructed
- Synthetic plain Netherite and FortuneIII Netherite tools supply full vanilla tier context to modern loot tables. They are ephemeral and never enter inventory. Modern raw ore/block/entity loot distributions and named random streams differ from1.7; no manual Luck multiplier is invented. One chance1 float draw per resulting stack is retained before emitting native stacks, but total RNG/item sequence parity is not claimed
- Modern COLLIDER/no-fluid shape tracing, loaded/build-height/config/mayInteract/native BreakEvent and final-break recheck are compatibility/safety adapters. Client packets never choose coordinates/range/Fortune. UUID/dimension/identity/nonfinite-aim/input/game-time fences are lifecycle adapters
- AbilityProgress/common catalog stores Double mastery/thresholds; the existing .8 Double learning boundary is preserved rather than globally changing prior checkpoints to Float comparisons. Source arithmetic in the held context is Float captured. This is a tiny threshold representation difference at Float rounding boundaries
- Corrupt/nonfinite/negative modern CP/overload/capacity, malformed levels and nonfinite mastery fail closed before creating/spending a context. Post-start corrupt resources close before world work. Finite ordinary failed CP retains the original final mining tick
- Modern render/audio scheduling, server reconciliation, resource caps, packet audience timing, and Java random sharing cannot prove old-engine pixel/audio/session replay parity from headless tests

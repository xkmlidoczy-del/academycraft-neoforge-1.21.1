# Remaining Teleporter skills: final active-skill stage

Pinned upstream: AcademyCraft classic 1.0.7 commit `00d19ec0cf538f61c1095c9292f5ee6863db4521` and LambdaLib 1.2.3. Bundled original source notices are retained. New implementation files retain GPLv3 notices; LambdaLib geometry remains MIT.

## Source behavior retained

- `location_teleport`, level3: original penetrate `.8` plus mark `.8` learning prerequisites, float saved coordinates retained through player clone/death, ordered/reindexed location IDs, 16-character names, strict mastery `> .8f` for cross-dimension use, overload240 and CP `lerpf(200,150,exp)*dimensionPenalty*max(8,sqrt(min(800,floatDistance)))`. It includes the player plus original living/dragon-part selector within inclusive5 blocks and strict float volume `<80`. Same-world offsets and orientation persist. Consumption uses the classic force path after legitimate CP availability succeeds. Experience measures distance **after** movement (`.015f` in normal successful jumps), then cooldown truncates `lerpf(30,20,updatedExp)`.
- `shift_tp`, level4: location `.5` prerequisite; captures mastery on context creation; requires a held block; original block-only eye ray, adjacent hit face and negative-coordinate truncation; CP260→320, overload40→30, normal damage15→35, range25→35 and cooldown100→60. The client receives its particle-stream execution before the placement/CP check. A denied release ends the context and earns nothing. Placement consumes one survival block; targets are re-traced **after** attempted placement and use the original strict line-box algorithm with living/dragon parts. Source critical passives, ordinary native armor/protection, target-count experience `(1+n)*.002f` remain in place.
- `flashing`, level5: shift `.8` prerequisite; captured mastery; initial CP80→60 and overload250→180; fixed original A,D,W,S local IDs1,2,3,4 and direction rotationZ(pitch) then rotationY(-90-yaw) using legacy float lookup-table trigonometry. Directional **release** spends13→6CP, resets fall distance, earns `.002f`, and increments teleport count. Bound ability-key release keeps the mode alive. Per-tick overload floor and preincrement `ticks > max_time` termination remain, with max60→150 and termination cooldown900→400. Local gravity compensation preserves `.072` for39 playing START ticks, ending on40. Activating another ability ends the Flash mode.

`PresetSkills.IMPLEMENTED` gains these actual skills, and common `SkillAvailability` continues deriving from that implementation set. Original catalog metadata is unchanged. All three can be genuinely learned through the physical Normal/Advanced developer route with original prerequisite, tier, finite IF and stimulation gates; target mastery stays zero until gameplay trains it.

## Modern adapters and remaining limitations

- Location GUI/network state uses persistent modern dimension resource keys and server-owned saved-list IDs. Legacy arbitrary Location payloads and unbound skill-name requests are not accepted. Server lifecycle/world-border/build-height/finite-value checks protect actual execution. List capacity is256; long lists scroll in the native screen. Dimensions display modern resource names rather than legacy provider display names/numeric IDs. The native edit field uses modern Minecraft text input and its editing glyph/caret layout; panel geometry, original artwork, row spacing, `.24` scale, palette and staggered fades are retained.
- Cross-dimension movement uses the official modern entity teleport APIs and loads the destination chunks. Companion offsets are captured before the transition, avoiding legacy removed-entity/portal-transfer reference inconsistencies. Native dimension transitions may reset velocity/fall state through the engine. Cross-dimension nonplayer replacement/portal behavior and multipart dragon movement need main runtime QA.
- Shift uses the actual modern BlockItem placement lifecycle, including modern block-state orientation, block-entity components, block placement protection and native placement sounds. The captured source placement guard, unconditional survival-item decrement after a guarded attempt, post-placement re-trace and ability costs are retained. Some custom BlockItem special placement semantics differ from obsolete `placeBlockAt`; native and third-party block cases need QA. Empty-hand swaps fail safely instead of reproducing the original null dereference.
- Flash direction packets carry an active-context nonce plus exact ordered hop sequence and bounded ID. Replays, malformed packets and foreign contexts fail. Failed legitimate hop attempts still advance the sequence so later releases remain usable. Authenticated Location GUI failures dispose the closed-screen session so it can reopen. The context accepts up to4096 directional attempts; no per-tick artificial hop restriction is added. Pending/server-ended late packets are guarded by entity UUID, token, nonce, connection and world epoch.
- Shared `CalcEvent.SkillPerform`/per-skill consumption/config arithmetic is **not fully restored**; these skills use the existing common CP/training adapter and source default curves. Existing global damage/attack-player/destroy-block settings and source-style damage/block permission hooks are used. Legacy per-world numeric destruction whitelists, every source config override and external skill-performance listeners remain outstanding shared work.
- Source achievement facts and teleport count are retained as persistent facts. This is **not the full original achievement/advancement registry/UI**. The modern counter saturates instead of overflowing at `Integer.MAX_VALUE`.
- Original textures, GUI XML and Ogg bytes are hash verified. Shift corner markers/stream and Flash marking biped use the original mesh/timeline/media through modern GPU adapters. Native OpenGL pixels, font availability, translucent/depth ordering, physical key precedence, positional sound mixing, the original actor-following Flash sound adapter, actual Ogg playback and client-only gravity prediction have **not been executed or pixel/audio verified here**. Hash/source-oracle tests do not establish full client fidelity.

No Gradle task, Minecraft server, client, GUI or recording is run by this stage. Main owns promotion, aggregate build and native server/client QA.

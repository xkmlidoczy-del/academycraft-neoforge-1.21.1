# Remaining fidelity and verification limits

This stage closes the missing shared SkillPerform consumption mutation, source normal/force scaling distinction, capacity training/event order, data-config hooks and the classic optional-float getter bugs. It preserves the tested port's default arithmetic and all mapped skill formula/capture quirks. It is an isolated common/server change; no production promotion, Gradle, server, world, client, GPU, audio or UI execution was performed here.

The following source contracts cannot be claimed as fully faithful in this lane:

1. **Whole-player float storage.** The existing port persists CP, overload, training and EXP as doubles. Converting all state/ticks/persistence to legacy floats would change established default behavior and is outside this narrow seam. Unmodified float event copies retain their original double-backed amounts; mutation and nonunit source scaling use float values. An independent pre-change oracle verifies default bits; a second independent CPData float oracle verifies50,000 individual operations within explicit1–3float-ULP bounds and deliberately detects the retained storage-rounding difference. This is not a bit-exact whole-player float port.
2. **Unsafe source arithmetic/config ranges.** Classic permits negative CP refunds, negative overload, NaN poisoning and some infinity cases. Existing modern finite/nonnegative cost guards are preserved and applied after mutation; source-style optional-key lookup errors still propagate. Recovery delays/data spec ranges remain bounded. Direct arbitrary state mutation by an extension is not a supported rollback contract.
3. **Client simulation.** Classic CPData can simulate consumption/events on both sides. The modern physical effects/input system is server-authoritative and this event adapter binds ServerPlayer only. No new client prediction or client SkillPerform transport is introduced.
4. **Arbitrary callback reentry/state mutation.** Direct common nested perform keeps source ordering. Native wire/start admission and focused stale-object guards deliberately prevent problematic nested world actions. This differs from the source's unguarded extension behavior. There is no rollback of earlier source-ordered transfers, ammunition decrement, ball creation, event-listener side effects, or arbitrary world changes. Failed-final-tick continuations and source resource/overload termination quirks are retained; explicit modern lifecycle disposal is fenced where mapped. Equal-priority external listener ordering belongs to NeoForge.
5. **Permission/feature settings beyond numeric consumption.** Existing global PvP/terrain settings remain in use. This lane adds source numeric optional keys and data settings; it does not add per-skill enabled/destroy_blocks UI, configurable entity-difficulty/exclusion lists, or an HOCON compatibility importer. Permission callbacks occur at existing source/modern protection sites; they are not replayed simply because a consumption listener exists.
6. **Other pre-existing ports.** Skill-specific fidelity limits in the frozen teleporter/vector/other lanes, including ray/physics/world/entity/audio/rendering differences, remain applicable. No progression prerequisites, input routes, other skill formulas, or effect assets were changed here.
7. **Runtime acceptance remains pending.** Six native fixtures compile but are unrun. The parent must run native/server checks after integrating all final lanes, then exercise natural Developer learning, config changes, actual SkillPerform listeners, force/creative play, cross-dimension/lifecycle disposal, placements/protection, release recursion, HUD/input, and sound/GPU behavior. The passed headless checks do not establish those outcomes.

Canonical resources are57 exact source/license files plus a classpath manifest and independent compatibility/oracle models. Upstream additional license notices remain preserved; private development only is authorized. No publication, push, paid action, or use of the user's computer occurred.

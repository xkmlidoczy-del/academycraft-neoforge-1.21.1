Key-abort, preset changes, deactivation or interference never fire. Early key-up<20 has no EXP/cooldown. The source has client-side20tick permission but no server-side minimum; the modern server validates its own20ticks, a security adaptation with latency/timing differences explicitly unclaimed.

Costs and shot/reflection parameters retain captured mastery even if other training changes it during the hold.

## MineRayBasic

Range10; harvestlevel2; captured Float speed.2->.4, CP12->7, startup overload200->150 floor, release/abort cooldown int(40->20), EXP.0005 per completed block. No entity damage is produced. The source basic visual is15units and follows the client caster, deliberately different from server mining range.

On each paid or FAILED-consumption tick, block tracing still runs. First acquisition posts source permission and tests harvest level, captures block hardness, and performs NO subtraction or particles. Only a subsequent tick hitting the same coordinates subtracts speed. Negative hardness becomes Float.MAX_VALUE. A miss/changed target resets coordinates and progress. Rejected targets are retested on later ticks, with no progress particles. First acquisition passes OLD stored coordinates for the source `getHarvestLevel(world.getBlockMetadata(x,y,z))` bug; the pure world interface retains and tests this explicit input.

A progressing tick does not recheck the original harvest/hardness. If another actor replaces the block at that coordinate, source breaks the CURRENT block after the old hardness completes, even if replaced by bedrock. That executable quirk is preserved, with a compiled native replacement fixture. On completion basic break sound.5volume/1pitch precedes fortune0/dropChance1 drops then setting air; EXP adds.0005. Coordinates reset to(-1,-1,-1) BEFORE particles are sent, preserving misplaced sentinel particle emissions. A failed CP tick can still finish a block, train and emit those particles before termination cooldown. No cooldown/EXP is applied on lifecycle discard, unlike ordinary release/abort.

## World, transport and lifecycle adapters

Each owned server context captures its actual AbilityProgress identity, ServerLevel, positive token, input correlation and start audience within25blocks plus caster. World ticks are applied at most once per actual world tick; repeated releases/packets cannot double spend or replay attacks. Packets carry caster entity ID AND UUID, server token/input, ray index0/1 or mining tick index. Starts/ends/geometry are common-only; client rendering and audio are fenced separately. End recipients remain the start audience after moving away. Finite spend persists through existing AbilityStorage. Contexts never persist over restarts.

Death/logout/clone/category/learned loss/dimension change/server shutdown discard without stale-world damage, EXP, cooldown or held client effects. Ordinary key abort semantics are source semantics (Meltdowner no shot, Mine cooldown). Lifecycle discard differs intentionally from classic ContextManager's universal termination behavior and is documented rather than silently claimed identical.

Source BlockDestroyEvent is represented by common cancellable SkillBlockDestroyEvent, including air probes, then native BreakEvent/mayInteract/load/build-height checks preserve modern world protection. Mine break additionally rechecks native protection at final action; canceled modern final break still reaches original EXP/sentinel logic, because original s_onTick has no callback success return. Those additional protection gates and current chunk boundaries are adaptations. Existing hooks/config/damage-scale/PVP/armor behavior remain authoritative; decoration attacks are suppressed when destruction is disabled, as source ctx.canAttack does for paintings/item frames.

Modern harvesting uses needs/incorrect-tool tags to map iron tier2. Minecraft1.21 has no1.7metadata API, so the native harvest adapter cannot reproduce a modded target block interpreting metadata fetched from unrelated old coordinates; the pure source interface/oracle records that bug, but full modded metadata parity is a known limit. Modern native loot tables use unenchanted iron pickaxe context for basic mining and netherite pickaxe context for the harvest-independent wide beam to recover source no-silk/fortune0 vanilla drops. This does not give a tool to the player. Version-changed vanilla/modded loot tables, modded tier tags, inventory/NBT drops and loot API RNG scheduling require native audit and are not asserted byte-identical.

Source global RandUtils/Motion3D RNG streams become server-world RNG, retaining sampling distributions/Float formulas, but exact seeded inter-mod random sequences are not claimed. Modern entity/damage-event/world-tick/packet/render scheduling, spectator/death/security checks, geometry query semantics and multiplayer latency differ. Reflection event ordering against other mods is inherited from NeoForge. See client visual fidelity and QA docs for unverified rendering/audio/external multiplayer limitations.
